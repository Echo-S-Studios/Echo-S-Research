# Code: `2026-06-charge-measure-coupling`

Producer scripts for **"The Charge--Measure Coupling on a Spectral Semiring:
Cyclicity, Composition, and a Parity-Graded Mahler Floor"** (v4, revised) --
`papers/2026-06-charge-measure-coupling/charge-measure-coupling-whitepaper-v4.tex`.

Each producer **computes** a result and **emits** machine-readable output to
`data/2026-06-charge-measure-coupling/`. This is the opposite role from the
suite in `tests/2026-06-charge-measure-coupling/`, which independently *asserts*
the same values: the producers here have no `assert`s, they regenerate the
paper's tables/tallies/constants as data. The two share no code (the producers
reimplement the two characters in `cmc_core.py` and never import from `tests/`).

## Run everything

```
py code/2026-06-charge-measure-coupling/constants.py
py code/2026-06-charge-measure-coupling/consolidation_ledger.py
py code/2026-06-charge-measure-coupling/parity_floor.py
py code/2026-06-charge-measure-coupling/charge_group_structure.py
py code/2026-06-charge-measure-coupling/tensor_adams.py
py code/2026-06-charge-measure-coupling/floor_bounds.py
py code/2026-06-charge-measure-coupling/finite_scans.py
py code/2026-06-charge-measure-coupling/salem_commutator.py
```

(`finite_scans.py` runs a two-stage screen over integer-coefficient windows and
takes the longest, ~1-2 min; the rest are seconds each.)

## Helper modules (not run directly)

| module | role |
|---|---|
| `cmc_core.py` | Independent implementation of the paper's two characters -- Mahler measure `M` (Character I) and charge group `Z/n` (Character II) -- plus the semiring operations (direct sum, tensor, Adams powers), reciprocity, integer charpoly reconstruction, and exact `Z/L` group helpers. High-precision `mpmath` root finding (50 digits) so the "is this argument exactly rational" decision is never made in double precision. Imported by every producer. |
| `cmc_io.py` | Provenance-stamped CSV/JSON writers. Every CSV gets a leading `# source: ...; generated by: ...` comment; every JSON gets `_source_paper` / `_generated_by` fields. |

## Notes on windows

`finite_scans.py` uses the verification suite's windows (`|c|<=6`, degree `<=4`),
which are narrower than the paper's stated windows (degree `<=7`; quartics
`|c|<=10`). Each output records both. These scans are the paper's `[computed]`
evidence, not proofs; a finite search can only support, never promote, the
`[computed]`/`[plausible]` tags.
